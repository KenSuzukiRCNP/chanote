# Contributing / building from source

Thank you for your interest. The two most useful contributions right now are
**school packs** for traditions other than Urasenke (no programming needed — see
[docs/school-packs.md](docs/school-packs.md)) and **translations** of `locales/*.json`.

## Build

Requirements: [Rust](https://rustup.rs) (stable), Node.js 20+, and on macOS the Xcode
Command Line Tools (`xcode-select --install`). Windows/Linux: see the
[Tauri prerequisites](https://tauri.app/start/prerequisites/).

```sh
npm install
npm run tauri dev        # run the app (first Rust build takes a few minutes)
npm run tauri build      # produce .app/.dmg (macOS), .exe (Windows), .AppImage/.deb (Linux)
```

Frontend only, in a browser with in-memory sample data (no Rust needed):

```sh
npm run dev              # http://localhost:1420
```

Tests and checks:

```sh
cargo test -p chanote-core   # database, packs, records, statistics, import/export
npm run check                # svelte-check / TypeScript
```

Development database override: `CHANOTE_DB=/path/to/file.sqlite npm run tauri dev`.

### Mobile (iOS / Android)

The same code builds for phones with Tauri's mobile targets. The layout switches to a
single column with bottom tabs below 768 px; file flows use the system pickers and, on
iOS, the app's Documents folder (visible in the Files app) instead of save dialogs.

```sh
# iOS — macOS with Xcode; without an Apple Developer Program membership the app can be
# installed on your own device only (Personal Team signing in Xcode, re-sign every 7 days)
rustup target add aarch64-apple-ios aarch64-apple-ios-sim
npm run tauri ios init             # once; creates src-tauri/gen/apple (commit it)
npm run tauri ios dev -- --open       # opens Xcode: set Signing → Team, pick your iPhone, Run

# Android — Android Studio (SDK, NDK, JDK 17) with ANDROID_HOME / NDK_HOME set
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
npm run tauri android init
npm run tauri android dev                       # emulator or USB device
npm run tauri android build -- --apk --debug    # installable debug-signed APK
```

`src-tauri/Info.ios.plist` is merged into the generated iOS Info.plist.
`crates/tauri-plugin-chanote-native` holds the small Swift part used on iOS (folder picker
with a security-scoped bookmark for sync, iCloud download requests); it is built and linked
automatically by `tauri ios dev/build`. Sync itself is plain Rust in
`crates/chanote-core/src/sync.rs` (format and rules described at the top of that file). The release
workflow builds an Android APK (release-signed when the `ANDROID_KEYSTORE_B64`,
`ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD` secrets exist, debug-signed otherwise;
`scripts/android-signing.py` wires the keystore into the generated Gradle file).

Browser mock of the phone layout: `npm run dev`, then open
`http://localhost:1420/?mobile&platform=ios` in a narrow window.

## Layout

```
src/                  Svelte 5 + TypeScript + Tailwind frontend
  lib/api.ts          typed wrapper over Tauri commands (falls back to a browser mock)
  lib/i18n.svelte.ts  UI strings and tea-term display modes
  routes/             screens: records, editor, statistics, lists, settings
src-tauri/            Tauri shell: command definitions only, no logic
crates/chanote-core/  SQLite schema + migrations, records, vocabulary, statistics,
                      import/export, attachments, backup — independent of Tauri
packs/urasenke.yaml   school pack (procedures, shelves, hearths, utensil categories)
locales/              ja.json / en.json
samples/              fictional sample dataset (generated by scripts/gen-sample.mjs)
docs/screenshots/     images used by the README
```

Design rules that keep the code easy to change:

- Anything that touches the database lives in `chanote-core` and has a test.
  `src-tauri/src/lib.rs` only converts between IPC and core calls.
- Every selectable field distinguishes *not entered* (`NULL`), *unknown* (`'?'`),
  *not applicable* (`'-'`) and a value. Statistics respect that.
- Tea terms are data (`vocab` table, seeded from a pack), never string literals in code.
- The export JSON is the interchange format; keep it backward compatible
  (`schema_version` in `crates/chanote-core/src/export.rs`).

## Releases

Releases are built by GitHub Actions from a `v*` tag (`.github/workflows/release.yml`);
`scripts/bump-version.sh X.Y.Z` sets the version in the three places that must agree.
Before tagging, move the `[Unreleased]` items in [CHANGELOG.md](CHANGELOG.md) under a new
version heading with the date, and add the version's link at the bottom of the file.
macOS builds are ad-hoc signed (`bundle.macOS.signingIdentity: "-"`), which needs no Apple
Developer account; the workflow file explains what to add to sign and notarize instead.

## Icon

Source: `assets/icon.png` (1024×1024, transparent outside the circle).
Regenerate with `npm run tauri icon assets/icon.png --ios-color "#f8f5ef"`. Besides the
desktop icons this writes `src-tauri/icons/android/` (copied into the Android project by
`tauri android init`) and, when `src-tauri/gen/apple` exists, the iOS app icon set there.
iOS icons must be opaque: if Xcode warns about an alpha channel, flatten the PNGs in
`gen/apple/Assets.xcassets/AppIcon.appiconset` onto the paper colour `#f8f5ef`.
